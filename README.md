# 만기 월드 (Mangi World)

Canvas로 그리는 싱글플레이 액션 RPG입니다. 게임 본체는 **`index.html` 한 파일**이며 CSS, JavaScript, 타일 이미지가 포함되어 있습니다. 서버 API, 계정, 빌드 또는 런타임 npm 패키지가 필요하지 않습니다. Google Fonts를 불러오지 못해도 기본 글꼴로 동작합니다.

## 실행

저장소 루트에서 Python 3 정적 서버를 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 이 서버의 `index.html`을 엽니다. Node.js가 설치되어 있다면 `npm start`도 같은 서버를 실행합니다. 게임 실행만을 위해 `npm install`을 할 필요는 없습니다. `index.html.html`은 별도 과거 사본이며 현재 실행·테스트 대상은 `index.html`입니다.

## 개발과 검증

Node.js 20 이상과 Python 3을 사용합니다. Playwright는 개발용 의존성입니다.

```sh
npm ci
npx playwright install chromium
npm test
```

Linux에서 브라우저 실행용 시스템 라이브러리가 없다면 Playwright의 공식 `npx playwright install --with-deps chromium` 명령을 사용합니다. 시스템 Chromium이 `/usr/bin/chromium`에 있으면 테스트가 이를 사용하므로 별도 브라우저 다운로드는 필요하지 않습니다. 다른 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다.

클라우드 환경처럼 홈 디렉터리에 npm 캐시를 쓸 수 없는 경우:

```sh
npm ci --cache /tmp/mangiworld-npm-cache
npm test
```

개별 검증은 `npm run test:save`, `npm run test:session`, `npm run test:input`, `npm run test:timing`, `npm run test:layout`, `npm run test:objectives`, `npm run test:equipment`, `npm run test:combat`, `npm run test:accessibility`, `npm run test:admin`으로 실행합니다. 테스트는 자체 임시 서버와 격리된 브라우저 저장 공간을 만들고 종료 시 정리합니다. 게임 서버를 미리 실행할 필요가 없습니다. 실패는 0이 아닌 종료 코드로 반환됩니다.

GitHub Actions는 `main` 푸시와 PR에서 같은 테스트를 실행하도록 구성되어 있습니다. 테스트의 전제·검증 범위는 [tests/README.md](tests/README.md)를 참고하세요.

## 상태와 저장 코드 수정 시

단일 HTML을 유지하면서 저장과 세션 전환의 책임을 구분합니다.

| 책임 | 함수·데이터 |
| --- | --- |
| 저장 데이터 생성 | `getSaveData` |
| 파일 검증과 구버전 변환 | `normalizeSaveData` |
| 검증 완료 데이터와 장비·아이템 준비 | `prepareSavedSession` |
| 일시 상태·애니메이션·타이머 정리 | `resetSessionRuntime` |
| 대화창·알림·HUD 정리 | `resetSessionPresentation` |
| 준비된 진행 데이터 적용과 UI 갱신 | `restoreSessionState` |
| 불러오기 후 플레이 시작 | `applySaveData` |
| 시작 상태 | 입력 전 초기값을 보관한 `INITIAL_GAME_SAVE`, `INITIAL_PLAYER_STATE` |

- 새 게임은 초기 진행 데이터를 복원한 뒤 도입 스토리를 시작합니다. 다른 슬롯의 레벨·퀘스트·장비·각성을 이어받지 않습니다.
- 불러오기는 검증과 아이템 준비에 성공한 뒤에만 현재 세션을 교체합니다. 잘못된 파일 때문에 진행 중인 게임의 효과나 루프를 중단하지 않습니다.
- 메인 메뉴 복귀는 필요 시 자동 저장에 성공한 뒤 초기 상태로 돌아갑니다. 새로고침 없이 돌아오므로 페이지 종료 이벤트가 중복 저장하지 않습니다.
- 저장하지 않는 전투 효과·버프·빙결·투사체·위험 구역·보스 재소환 대기·훈련 기록·쿨타임은 새 게임/불러오기에서 초기화합니다. 지속되어야 하는 진행도는 저장 형식에 명시적으로 추가해야 합니다.
- 소리·화면 흔들림·자동 저장의 현재 설정과 정적 이미지·아이콘 캐시는 세션 전환 중 유지합니다. v4.0.0부터 자동 저장·볼륨·UI 글자 크기·히트스톱·효과 강도·키 설정도 재실행 후 유지합니다.
- 세션을 변경하는 지연 작업은 `setSessionTimeout`과 `clearSessionTimeout`을 사용합니다. 새 세션으로 이전 콜백이 넘어가지 않도록 정리 대상에 포함됩니다.
- 스토리와 게임의 `requestAnimationFrame`은 각각 하나만 유지합니다. 새 전역 상태·효과·타이머를 추가할 때 초기화 경로와 회귀 테스트도 함께 확인합니다.

현재 저장 형식은 버전 5이며 버전 없음/1/2/3/4의 기존 저장을 변환해 불러옵니다. 중요한 저장은 브라우저 삭제·기기 변경에 대비해 파일로 내보내세요.

## 입력과 일시정지 (v3.4.4)

- 창 포커스를 잃거나 탭이 숨겨지면 이동 입력·속도를 해제하고 일시정지합니다. 창으로 돌아와도 자동으로 재개하지 않습니다. 계속하기 또는 Escape로 직접 재개합니다.
- 대화·상점·알림·탑 선택·저장·설정 창이 열리면 게임 로직이 멈춥니다. 생존 진행도·쿨타임·버프·투사체·피해가 진행되지 않으며, 메뉴 뒤의 스탯·가방·퀵슬롯 클릭도 막습니다. 해당 메뉴 자체의 구매·대화·설정 버튼은 사용할 수 있습니다.
- Escape는 겹친 창의 표시 순서에 따라 맨 위부터 처리합니다. 저장·설정을 닫으면 일시정지 메뉴로 돌아갑니다. 포커스 이탈로 대화창 위에 일시정지 메뉴가 열린 경우 두 창을 각각 닫아야 플레이가 재개됩니다.
- 키 반복 입력은 새 동작을 만들지 않습니다. 이동과 충전 스킬은 최초 입력 후 키를 누르는 동안 유지합니다. 일시정지에서 키를 놓친 경우 재개 후 이전 입력을 이어받지 않으며, 충전 중이던 스킬은 재개 후 해제된 입력으로 처리합니다.
- 텍스트 입력 중이거나 Ctrl·Alt·Meta를 누른 단축키는 게임 명령으로 처리하지 않습니다. 일시정지 중 Tab은 메뉴의 기본 키보드 탐색에 사용할 수 있습니다.
- `gameplayPaused`는 게임 정지 여부, `canUseGameplayInput`은 입력 전달 여부, `releaseGameplayInput`은 입력 해제를 담당합니다. 새 모달을 추가하면 `GAMEPLAY_OVERLAYS`와 Escape 처리·테스트도 갱신하세요.

## 시간과 성능 (v3.4.5)

게임 로직은 `stepGame`에서 1/60초씩 진행하고 `loop`가 RAF 간격을 누적합니다. 30Hz에서는 보통 두 틱, 60Hz에서는 한 틱을 처리하며 144Hz에서는 필요한 화면 프레임에서만 틱을 처리합니다. 이동·투사체·스킬·생존·보스 대기·버프·마나 회복의 기존 60Hz 수치와 밸런스는 유지합니다.

| 기준 | 처리 |
| --- | --- |
| 전투 시간 (`frameCount`) | 실제 진행한 전투 틱. 평타 대기, 이동, 스킬/궁극기 대기, 상태이상, 훈련장 기록 등 |
| 활동 시간 (`autoSaveTimer`) | 처리한 고정 틱. 히트스톱을 포함해 1,800틱마다 자동 저장 |
| 스토리/알림 시간 | 스토리는 RAF 시각, 알림·메뉴 재접촉 방지는 세션에 묶인 브라우저 타이머. 저장 날짜만 `Date.now()` |

- 메뉴·포커스 정지 중에는 두 게임 시계 모두 멈추고 누적 시간을 비웁니다. 재개 시 밀린 공격이나 생존 시간을 한꺼번에 적용하지 않습니다.
- 히트스톱은 전투와 전투 효과를 멈추고 직전 표시 프레임을 유지합니다. 자동 저장 주기는 멈추지 않습니다.
- 한 화면 프레임에서 최대 5틱까지만 따라잡습니다. 그보다 많은 밀린 틱은 버리고 250ms를 넘는 긴 공백은 통째로 건너뜁니다. 극심한 저성능 상황에서는 실제 시간보다 진행이 느려질 수 있지만 무한 따라잡기와 피해 몰아주기를 막습니다.
- 평타는 저장 날짜/시스템 시계 대신 전투 시간을 사용하므로 시계 변경이나 메뉴 대기로 대기시간을 우회하지 않습니다. 입력 시점은 60Hz 틱 단위로 양자화됩니다.
- 스킬 쿨타임 갱신과 HUD 표시를 분리했습니다. 배우지 않은 무기로 바꾸어 HUD가 숨겨져도 기존 쿨타임은 진행합니다.
- 업데이트와 그리기가 결합된 기존 효과 함수는 유지합니다. 따라잡기 중간 틱은 빈 clip으로 래스터 출력을 생략하고 마지막 틱만 표시하며 HUD도 화면 프레임당 한 번 갱신합니다. 중간 틱의 도형 계산 자체가 전부 생략되는 구조는 아닙니다.
- 반복 바닥은 작은 원본 타일의 CanvasPattern을 재사용합니다. 패턴 캐시는 최대 64개이고, 패턴 변환 미지원 환경에서는 기존 타일 반복 그리기로 돌아갑니다. 프레임 전체를 거대한 이미지로 캐시하지 않습니다.
- `loopStats`는 세션별 처리 틱·전투 틱·표시 횟수·버린 시간·최대 따라잡기 횟수를 관찰하는 개발용 값이며 저장하지 않습니다.

## 화면 크기 대응 (v3.4.6)

- Canvas의 내부 해상도와 게임 좌표는 800×900으로 유지합니다. `fitGameLayout`이 실제 여유 폭·높이에 맞춰 표시 비율을 계산하며 창 크기와 브라우저 표시 영역 변경에 대응합니다.
- 폭 1,280px 이상에서는 양쪽 패널을 함께 표시하고, 그보다 좁으면 상단 버튼으로 정보·가방 패널을 엽니다. 패널을 여는 동안 게임은 멈추지만 해당 패널의 스탯·아이템 조작은 가능합니다. 기존 일시정지나 다른 모달이 열려 있으면 그 상태를 우선합니다.
- Escape/닫기/바깥 영역 클릭으로 패널을 닫고 열었던 버튼으로 포커스를 돌립니다. Tab은 열린 패널 안에서 이동합니다. 데스크톱 배치로 전환하면 접이식 패널과 배경 가림을 정리합니다.
- 월드 그림만 비율대로 줄이고 메뉴·대화·상점·저장·HUD는 `game-stage`에 배치해 글자 크기를 유지합니다. 게임 표시 폭이 520px보다 작으면 의뢰·던전 정보 영역을 정보 패널로 옮깁니다. 저장을 불러온 뒤에도 의뢰 표시를 복원합니다.
- 작은 화면의 가방 칸과 장비 아이콘은 패널 폭에 맞추고 물약 구매 버튼은 2열로 배치합니다. 긴 메뉴와 패널은 자체 스크롤을 사용합니다.
- 툴팁은 변환된 게임 요소 밖의 body에 두고 화면 네 변 안으로 위치를 제한합니다. 마우스 이동·클릭과 크기 변경 때 실제 Canvas 사각형으로 조준 좌표를 다시 계산합니다.
- 도움말은 HTML 강조와 실제 처치/정예/생존 조건을 사용합니다. 파비콘은 기존 ICO 데이터를 유지한 `favicon.ico`로 제공하며 외부 글꼴 없이도 게임을 실행할 수 있습니다.

검증한 화면은 1920×1080, 1600×900, 1366×768, 1280×720, 1024×768, 800×600, 320×568, 844×390, 320×360입니다. 화면 배치 대응 범위이며 게임 조작은 기존 키보드·마우스 기준입니다. 터치 전용 이동·공격 버튼은 별도 기능입니다. 현재 저장 형식과 변환 정책은 아래 목표 안내 절을 참고하세요.

## 다음 목표와 진행 안내 (v3.4.7)

- HUD의 **목표 선택**, 일시정지 메뉴의 **목표와 진행**에서 메인·서브·반복 의뢰, 던전, 스킬 습득, 각성, 탑 목표를 살펴보고 추적합니다. 작은 화면에서는 정보 패널에 같은 HUD가 있습니다.
- 자동 안내는 미수령 보상, 수락한 메인/서브 의뢰, 초반 의뢰 수락, 열린 스승 결투, 던전·각성·탑을 진행 상태에 따라 추천합니다. 반복 의뢰는 직접 추적할 수 있고 완료 보상은 자동 안내에도 우선합니다. 선택 자체가 의뢰 수락이나 보상을 실행하지 않습니다.
- 권장 레벨과 실제 입장 제한을 구분합니다. 네 사냥터는 권장 레벨이고, 왕성 Lv.30·마왕성 Lv.80·엘프 마을의 늑대왕·마법사 탑의 사령왕·각성/무한의 탑의 대마왕 조건을 반영합니다. 완료/잠긴 목표는 선택을 막고 기존 선택이 그 상태가 되면 자동 안내로 전환합니다.
- 던전은 일반 25마리, 정예 3마리, 90초 생존, 보스 상태를 표시합니다. 수락 전/보상 대기 의뢰는 길드로, 스킬은 스승으로, 각성은 부족한 재료·개별 과제·재대결 단계로 안내합니다. 검 각성의 탑 과제는 실제 판정 값인 **최고 30층 클리어 기록** 기준입니다.
- `buildObjectives`와 `currentObjective`가 상태로부터 목표를 계산하고 `objectiveNavigation`이 현재 맵의 다음 출구/포탈 또는 현재 구역의 수행 내용을 계산합니다. 열린 연결만 탐색하며 던전 안에서는 완료 조건을 충족한 포탈만 안내합니다. 결투 중에는 존재하지 않는 출구를 표시하지 않습니다.
- 노란 화살표는 로컬 방향 표시입니다. 이동·장애물 회피·전투는 플레이어가 수행합니다. 목표 HUD는 약 0.2초 간격과 주요 이벤트에서 갱신하고 같은 텍스트는 다시 쓰지 않습니다. 기존 업데이트/표시 구조와 60Hz 시뮬레이션은 유지합니다.
- 목표 창은 게임을 멈추고 Tab 포커스를 내부에 유지합니다. 일시정지에서 열었거나 포커스를 잃었다면 닫을 때 일시정지 메뉴로 돌아갑니다. 짧은 화면에서는 일시정지 메뉴도 위쪽부터 스크롤합니다.

## 난이도와 밸런스 (v4.3.0)

설정에서 쉬움·보통·어려움을 선택합니다. 시작 화면의 선택은 새 게임에 적용하고, 진행 중에는 안전한 지역에서만 변경할 수 있습니다. 난이도 변경은 회복·쿨타임 초기화·추가 보상을 제공하지 않습니다. 전투 중 설정 항목은 비활성화합니다. 난이도는 환경설정과 별개로 각 진행 저장에 포함합니다.

기존 저장은 형식 6으로 변환하여 보통 난이도로 불러옵니다. 이전 경험치 진행 비율을 새 성장 곡선으로 옮기고 레벨·아이템·골드는 유지합니다. 관리자 복구 지점과 전용 저장에도 같은 변환을 적용하며 관리자 프리셋은 선택한 난이도를 유지합니다.

활·지팡이 피해, 마나 회복, 적 체력 곡선·정예 보상·성장 요구량을 조정했습니다. [이전/변경 수치와 측정 조건](BALANCE_NOTES.md)을 참고하세요. 전투 정보창과 적 머리 위의 준비 시간·보스 HP·저체력 테두리로 현재 상황을 확인할 수 있습니다. 관리자 도구에서 전투 초기화와 함께 난이도를 변경하고 이론 평타 DPS와 실제 피해 측정을 비교할 수 있습니다.
